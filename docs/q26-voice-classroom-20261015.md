# 第26题有声老师课堂

2026-10-15。本轮把第26题三角形数课堂接入真实普通话配音，声音、板书与点阵使用同一条Remotion时间线。范围是当前第26题的主问题；其他题和其他学科没有在本轮获得配音支持。以下分别记录真实主课、历史已核对答疑的有声续讲、实际MP4，以及本次新答疑服务中断。

## 教学内容与声音来源

沿用第26题已经核验的题面r4、教案v3、partId=`main`，没有重新调用AI生成解答。老师主课讲稿是对这份教案的人工口语改写，分七章、29条语音片段：读题与认识点阵、建立方法、连续自然数求和、展开原题、抵消求差、独立检验、方法收束。保留全部四个真实步骤及其理由、检验与误区，没有用外部参考答案替换AI教案。

讲稿先逐行认识1、3、6、10、15、21，再以第6个减第4个的小例建立抵消方法，回到第24个减第22个，最后计算23+24=47并用300−253验算。明确区分序号、行数和总点数；两份253点省略块都保留，省略画法不等于丢掉点数；数学抵消不等于石子消失；47是点数，不是面积。字母n口述为“字母恩”，T的指代明确；求和公式先说括号里的n+1，再乘n、最后除以2，避免听成n×n+1。

实际TTS使用开源`edge-tts`访问在线Edge语音服务，声线为`zh-CN-XiaoxiaoNeural`，rate=`-8%`。它提供真实合成音频，不能据此声称讲稿由AI重新生成，也不能把合成声音称为真人教师录音。准备配音需要联网；Edge在线语音没有本项目约定的服务等级保证。向更多家庭推广前应选用有明确服务条款、稳定性与授权约定的专业TTS。已经准备的MP3和导出MP4保存在本机，播放不再次请求Edge合成。

## 用实际音频时长驱动课堂

准备配音先核验当前题面、教案、完整覆盖及四项检查，再逐片段合成MP3。每段用`ffprobe`确认有音频流，并按实际时长向上取整到30fps；不按字数猜测时长。每段语音后增加12帧观察间隔，每章后增加30帧停留。只有全部片段成功才发布ready配音；缺失片段、网络失败或时长核验失败不会发布有声课堂。

配音清单为每条片段记录全文、音频帧数、起始帧、观察间隔及对应动画窗口。窗口的`visualFrom/visualTo`是原`TeachingVisual`的canonical秒数，不是音频播放秒数；根据实际语音进度，将它映射到相应的动画位置。两端相等时保持板书，便于解释。

| 教学动作 | 对应原动画窗口 |
|---|---|
| 逐行成长 | 第k行从(k−1)×0.48秒开始；每行独立语音片段，第一至第六行逐次出现 |
| 小例消去共同部分 | 第1章的0.8至1.6秒，随后只数第5、6行 |
| 原题展示共同部分 | 第3章保留两份253点省略块；第23、24行对应1.3及1.6秒的进入动作 |
| 原题抵消与求差 | 第4章0.3至1.1秒标记共同部分抵消，2.1秒后的结果动作对应47点 |
| 独立检验与收束 | 沿原教案检查300−253=47，留下可复用的方法路线 |

Remotion的`Html5Audio`与动画放在同一个`LessonComposition`中。Player是主课唯一时钟；暂停、定位、重播、调速同时作用于声音与数学画面，缓冲时暂停时间线。同步口述字幕取当前语音片段，不依赖另一套语音计时器。网页的播放速度由Player控制；视频pace=1/2分别生成正常讲解/紧凑回顾，并同步改变音频及画面的节奏。

## 提问、补讲与续讲逻辑

开始填写疑问或点击快捷提问时，先一起暂停声音与板书，保存当前帧和此前是否正在讲课。提交给DeepSeek的现场包含题面与教案版本、小问、真实步骤、点阵状态以及配音片段信息；数学结论仍由服务端重新计算，不信任客户端提交的答案标签。

答复经过独立数学核对后，只有`status=checked`才允许制作补讲配音。补讲声音来自对应askId的真实已核对答复，不把预录答案冒充实时AI解释；未知数学口述符号会明确拒绝配音并保留文字。补讲期间主课停在原帧，不以答疑音频推进主课板书。

“听老师补讲”也支持当前questionId、revision、lessonVersion和partId匹配的历史已核对答复，按精确askId生成或复用声音。切换历史答复前先停止主课与旧补讲，防止新答复文字配上旧声音；界面保留历史现场标记，不把它称为此次新追问。

补讲音频结束后，只有此前正在播放、当前题目/教案/小问身份仍相同、课堂仍在前台、仍处于老师模式且会话没有冲突，才从冻结帧继续。原先手动暂停的课保持暂停。切换题目、离开课堂、隐藏页面、答复未通过核验或补讲播放失败时不自动续讲；失败保留文字答复，允许用户主动重听或继续主线。浏览器限制声音自动播放时，明确展示“听老师补讲”，主课继续暂停，不能静默跳过补讲。

本轮已用此前真实DeepSeek核对通过的答复，完成真实Edge补讲、主课冻结及补讲结束后续讲的浏览器验证；本次新追问生成没有成功。两项证据分开记录如下。

## 有声视频与版本边界

导出请求提供`narrationId`时，服务端确认它与当前questionId、revision、lessonVersion、partId及教案SHA256一致，覆盖全部七个阶段，并核对每个MP3的音频SHA256。答疑补讲不能代替完整主课配音。任务复制本次批准的音频到视频私有目录，冻结完整教案及配音清单；后续教案或原MP3变化不会悄悄改写已排队视频。

有声视频仍由同一Remotion组件按1280×720、30fps、H.264视频与AAC音轨渲染。渲染完成后用`ffprobe`确认存在音频流才允许发布有声结果。不提供`narrationId`仍是图文无声视频；不能把请求已经排队、`hasAudio=true`或渲染进度当作媒体验收成功。

当前接口及代码实现详见[API契约](api-contract.md)。配音和视频保存在`data/runtime/narration/{uuid}/`与`data/runtime/videos/{uuid}/`，不入Git；文件接口使用固定UUID与片段白名单，不能指定任意本机路径。缓存身份包含题面和教案版本、教学内容SHA256、声线、语速、脚本版本与帧率；补讲另含askId和答复SHA256。脚本已更新至`q26-teacher-voice-2`，避免继续使用存在运算顺序口述歧义的旧配音。
