# 知间样卷真实核心后端交付记录

日期：2026-10-14。范围为本机单家庭核心流程；不是公开服务上线验收。

## 已实现

- `zhijian.app:app` 提供契约中的试卷导入、原图、校对、逐题和整卷老师课、追问、任务、覆盖计数、记录、课堂会话路由；额外补充任务重试及追问历史读取。
- 原图真实保存，派生页旋正；图片最多10张、PDF最多20页、批次总大小100MB。整页方向/题号清单与逐列高清提取均调用真实视觉模型。未配置密钥仍可保存原图，返回配置失败任务及零题目；不会读金标准来生成题面。
- `AI_BASE_URL / AI_MODEL / AI_VISION_MODEL / AI_REVIEW_MODEL` 与 `DEEPSEEK_API_KEY` 只在服务端读取。根 `.env` 不覆盖已存在的运行时环境；不会向 DeepSeek 发送 `OPENAI_API_KEY`。请求及响应证据不保存认证头或图片base64。
- 教案初次生成仅输入已确认题面，覆盖每个实际 `partId`，有目标、条件、先备、方法、步骤及理由、结论、具体验算、易错、收束。只执行固定数学组件，不执行模型提供代码。
- 生成返回后才读取独立金标准。金标准限定两张原始样卷的文件SHA；不按题号核验其他卷。补录UUID通过明确小问标签建立 `checks.partIdMap`；缺问、重复或含糊标签不能通过。
- 样卷结论单独比较，包括分数、无序多解集合、坐标、完整取得区间和受控AST线性式。第15题减号条件另查，错误0不能通过−24。
- 第二次调用逐小问审核条件与关键理由。每条要求必须有对应当前小问中的来源字段/步骤ID及逐字quote；另外每个实际stepId都须唯一覆盖explanation/reason/formulaLatex三项，九个教学字段goal/known/prerequisites/method/answer/verification/misconceptions/summary/scene也须逐项唯一审核。任何缺项、重复、false、非空issue、虚构quote或未解决问题都拒绝发布。只称 `auto_checked`，不称教师签审。
- 当前题面revision、任务状态、任务lease及当前小问生成lease均参与事务发布。修题、取消、重启回收或同题新任务之后，老响应不能发布。原始失败输出保留，重试建立新任务和lease。
- 识别重试只补尚不存在的主题号，不覆盖已校对或已确认题面。一题缺项/生成失败不应阻断其他完整题。
- 第19题每个小问数轴条件单独核验；第26题点阵限定22到24。最小值/闭区间、距离和的解集及参数解与场景计算一致。追问区分原题47与8层小样本36点、新增两行15。
- Postgres保存全部题面版本、教案版本、任务、追问、学习事件和课堂会话。原话、系统观察与主线阅读分开；会话保存拒绝题面和当前最新教案冲突，409不冒称保存成功。

## 已执行验证

在项目根运行：

```sh
PYTHONPATH=server .venv/bin/python -m pytest server/tests -q
```

最新源版输出：`66 passed in 63.04s`，无skip、无warning，compileall成功。数据库测试使用根配置的独立 `TEST_DATABASE_URL`，真实Postgres连接和事务，不以SQLite或内存替代。已配置TEST_DATABASE_URL时，数据库初始化失败会直接失败，不能以skip掩盖真实故障；全套验证独占执行。

有意义的回归包括：缺定义、缺小问、Q15错误答案、空理由、修改/取消/旧租约晚回、事件跨Store连接恢复、同版本新任务胜出、旧教案不能覆盖课堂、伪造review引用、审核自相矛盾、稳定UUID与语义叶小问映射、有限场景参数、a=-5固定点交换、场景与题面错配、原题与点阵样例分开，以及无密钥原图保存但不生成假题。

整卷内部两题并行测试先因串行无法启动第二题而失败，修改后通过：第二题仍等待时，第一题ready立即可读取、completedUnits=1；第三题失败后总进度=3，成功课程保留，最多同时处理2题。该调度测试仅以确定性异步边界代替付费AI调用，不计真实模型验证。

真实OCR任务发现进度收尾仍使用启动时的两页总数，覆盖了识别阶段更新的六列。新增回归先得到completedUnits=2的失败，随后改为完成时读取当前totalUnits，通过全套测试；未改变任何生成prompt或AI参数。

真实Q19/Q26首轮课程被结构和审核门禁拒绝后，明确了scene的kind/params结构、参数一致性和minimum的完整闭区间；审核只把尚未解决的数学矛盾列为inputIssues，quote要求连续原文。加入最多一次自动修复：首个未经gold生成的原始JSON与失败证据独立保留，修复只收到它自己的JSON、结构错误类别和经过删去参考解答的审核失败类别。修复后仍逐小问重新进行全部检查。测试先观察首次型错无法修复、二次未调用的失败，再验证可修复至ready及二次失败仍needs_repair，没有第三次生成。该测试是隔离夹具，不冒称真实模型课程。

原图定位允许随题面同版本校对，有限页内区域和实际pageIndex均核验。覆盖读取改为单连接两查询，未覆盖小问不能回退为ready。真实本机27题数据库单次coverage：旧版10.3623秒，新版0.6430秒；此为单次实测，不是生产p95指标。新的GET /api/papers/{id}另用TestClient连接真实样卷数据库测量，结果由本轮工具执行记录及根运行报告保存。

新来源定位测试一度创建缺url/width/height的无效纸张夹具，使测试API列表失败；已修夹具为真实契约形状，并只清理zhijian_test内这两种旧无效夹具纸张。未为生产public_paper添加掩盖缺字段的逻辑，也未清理生产样卷。随后46项全套独占通过。

独立实际内容审核随后发现，初轮auto_checked课程仍含额外错误的幂比较、数轴理由及“举例证明必然”等说法。只核验关键锚点不充分，因此本轮扩展了逐步骤和九字段审核；新回归在旧gate下真实放行而失败，修复后全套58项通过。错误旧课由根任务撤回，不由后端作者手工改写actual lesson。提示要求覆盖题设范围、0/1/等号和端点，区分示例与普遍证明，消除自纠矛盾；加权距离需要合法完整证明。

文本模型配置为deepseek-v4-pro时，请求明确启用thinking、reasoning_effort=high和max_tokens=32768；视觉Flash仍disabled/16000。Pro请求遇图片会在发送前拒绝，认证和Base URL规则不变。请求体分支由MockTransport验证，不计真实Pro模型能力实测。第15题第三项负系数的等价分数LaTeX与线性式均可通过条件门禁，正号与分子分母倒置拒绝；给定最小值反求参数仍输出numbers，直接求最小值才输出minimum。

更严格审核规则及58项测试并不自动证明真实新课程无误。整卷Pro重新生成、逐题及小问独立读取、现有失败和撤回记录，由根任务继续运行并记录。

追问定位另补4项回归：服务端按真实教学片段索引派生读题、方法、实际步骤和末页验算收束；前两页不再引用第一计算步骤，中间片段保留实际stepId与reason，末页提供verification及summary。索引非有效整数/越界、步骤与位置错配均拒绝。currentTeachingSlide/currentStep同时进入AI上下文与持久证据，模型无需猜索引含义。未改课程生成参数或提示，未停止正在运行的真实AI任务，未运行收费AI调用。

根任务实际Pro优先课程耗时较长后，授权当前调度调整为后台每批六题、全局Provider请求cap=8，dispatch仍最多两个任务。并发回归先观察原cap无法启动六/八个请求而失败，随后验证最多六题和最多八个HTTP请求、第九请求待释放后才发送、第一题ready及时可读、第一批失败后下一批继续，完成计数准确。此是隔离异步/HTTP夹具验证，不等于真实vendor并发性能。

Provider.json新增interactive=False关键字。后台Pro依旧thinking enabled/high/32768；ask和answer-review仅显式interactive=True时用同一Pro的low，二次claims核验、步骤位置与确定性场景facts均不变，Flash视觉仍disabled/16000。私有request metadata保留profile、interactive、startedAt/httpStartedAt/finishedAt、queueWaitMs及elapsedMs，错误或取消也记录结束。实际后台与追问响应速度及内容仍由根任务重新实测，不能根据低推理参数宣称更快或正确。

所有新增关键边界均先观察失败再改到通过；初始新模块收集失败也保留在工具执行记录。测试中的课程数据仅为隔离测试库的验证夹具，不计入真实样卷运行、模型准确率或孩子学习效果。

新Pro课程的独立阅读仍发现未经条件支持的“更近”判断，以及把不同中心对称说成原坐标异号。本轮仅补充生成与二审提示：距离、中点和倍数判断须有题设或明确图注依据，区间和示意图比例不能代替条件；对称须核对实际中心及坐标；易错提示指责孩子忽略某事实时，该事实也须成立。未加入逐题答案或向生成提供gold，未改审核算法、课程数据、AI参数，未停正在运行的整卷任务。该源版需新进程加载才会生效；已经运行的任务仍使用原进程载入的提示。64项测试和compileall验证源码回归，不代表这些真实内容错误已经修复，重新生成后的内容仍由根任务独立检查。

后续实际Q16修复审核返回不支持条目的source=null，原review_passes抛AttributeError导致该修复草稿未保存。已用同样的真实响应形状先复现两个失败测试，再将非对象来源明确记录为不支持的引用，不能因此放行supported=false或伪造支持。本地只读重放原始Q16响应现返回false及七项问题，不再异常；数学内容仍被拒绝，未手工发布或修改响应。Q18原引用逐字存在，但模型给itemIndex:[0]而非整数，保持拒绝并在审核提示明确单个从0起始整数，未自动改写该真实审核。生成提示另要求正文LaTeX有行内分隔符，formulaLatex字段不加分隔；普通和与和的绝对值分清，新增定理须解释原理及全域取得证明。无付费调用、课程数据改写或服务重启。

## 启动

项目根：

```sh
PYTHONPATH=server .venv/bin/python -m uvicorn zhijian.app:app --host 127.0.0.1 --port 8787
```

若启动脚本的cwd为server，则用 `../.venv/bin/python -m uvicorn zhijian.app:app --host 127.0.0.1 --port 8787`。配置密钥后重启，再重试保存的识别任务。

## 验收边界

本报告中的测试通过只证明后端规则及本机持久化；真实AI样卷原始输出、题面人工校对、26道完整题及38个可核验叶小问的授课覆盖，应由根任务运行并独立记录。未在本报告中宣称OCR准确率、真实教案通过率、教师审核或孩子学习效果。

当前整卷教案任务每批六题并行，provider全局请求上限8，dispatch同时最多两个任务；可与单题任务及课堂追问交错，仍由全局限流控制。未知新卷可以识别和生成待核验草稿，但没有独立答案核验时不能发布auto_checked课程。未实现音频、视频导出、账户授权、跨家庭访问或生产RAG。
